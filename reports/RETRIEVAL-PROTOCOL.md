# Frozen offline retrieval pilot

The campaign evaluates five original GitHub issue reports across two repositories. It makes no coding-model calls and does not establish a coding capability or cost frontier. Download metadata/source with `node experiments/retrieval/acquire.mjs` then `python experiments/retrieval/acquire-source.py`. Acquisition requires network access; scoring needs no network. Existing frozen artifacts should be retained rather than reacquired for reproduction.

Issue queries: micromatch/picomatch #62, #142, #187, #58; mrmlnc/fast-glob #499. Independent merged PRs #197, #198, #196, #199 and #505 provide grader labels. URLs, original issue bodies, dates, base revisions and PR head revisions are stored in `.suffice/retrieval/queries.json` and `labels-private.json`. No PR title, PR body or patch enters the query or index. A sixth candidate fast-glob #500 returned HTTP 404 during acquisition and was excluded before freezing; no scored attempt was removed. These are fresh relative to prior Suffice campaigns, not necessarily new bug reports, training holdouts or representative samples.

Only lib/ and src/ JS/TS files are retained from commit-pinned archives, excluding declarations. This includes src-contained tests in fast-glob. Documentation, manifests and external dependencies are excluded. Corpus selection is independent of repair filenames, but favors the existing JS/TS navigation tool's language coverage. Base snapshots are PR base SHAs; we did not execute original failures or upstream fixes. Labels indicate upstream repair locations, not causal necessity or validated repairs.

`node experiments/retrieval/run.mjs freeze` saved the SHA-256 manifest before scoring. `node experiments/retrieval/run.mjs` checks frozen source, policies, runner, queries and labels before and after evaluation. It writes all packets before reading labels for grading. Although one orchestrating process hashes labels for integrity, retrieval policies have no label parameter or access; this is an architectural separation, not an operating-system secrecy boundary.

Four arms use identical 60-line source units and matched 4096/8192 estimator ceilings. Lexical uses BM25. AST uses the existing `indexJavaScript` symbol definitions with deterministic issue-word substring matching; this is an automated adapter to current AST navigation, not a live agent performing `symbols`/`symbol_read`/reference loops. Dependency expands relative imports and reverse imports by one hop from the top three lexical files; it is not semantic call resolution. Hybrid combines normalized scores with weights 0.5/0.25/0.25. Full formulas are frozen in policy.mjs. No policy was tuned after scores. AST has no lexical fallback and may underfill budgets. Packing sorts deterministically and skips units too large for remaining space. Corpus chunks are nonoverlapping.

Budget estimator: **ceil(UTF-8 output packet bytes / 3)**, including path/line headings and source. This is not a provider tokenizer or a guaranteed 4K/8K actual-token limit. Queries and system/tool prompts are outside this source-context budget. The term "token" in JSON fields means these estimated units. Both budgets use the same estimator. Report actual utilization rather than pretending every arm uses the full budget.

File recall averages each task's fraction of touched labeled files retrieved. All-files counts tasks covering every labeled file. Hunk coverage is the fraction of old-side diff hunk lines included, averaged equally across tasks; unchanged surrounding context is included in hunks. Zero-length old hunks are represented by their anchor line. These are imperfect repair-location proxies: alternate valid repairs can touch different lines, tests are labeled as files when inside src/, and file presence can conceal missing relevant lines. Report both metrics. No independent dependency/caller semantic labels were constructed.

This is a bounded activation pilot: five tasks × four deterministic arms × two budgets = 40 offline retrieval packets, not 40 paid coding attempts. It has no stochastic repetitions, live repair, difficulty screening of Sol, baseline coding failures, inference, subscription billing or model-cache claims. Fixed arm order and shared-machine timing preclude latency claims. A pre-scored policy design exercise was not conducted; policy unit tests are post-scoring verification and did not change frozen code.

Run `node --test experiments/retrieval/policy.test.mjs` for meaningful budget, UTF-8, dependency-resolution, AST parse-coverage and label-independent ranking checks. Frozen files should not be edited to improve these scores. Any future policy change requires a new protocol/version and new issue holdout.
