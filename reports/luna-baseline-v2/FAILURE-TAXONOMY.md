# Post-hoc Luna failure taxonomy

This is a development analysis of preserved attempts, not a new scored cohort or an account of the model's private reasoning. Categories describe visible evidence and submitted code. No failure was repaired or replaced. All ten actor attempts completed: s02/i02 passed acceptance and eight were rejected.

Trace line numbers below refer to `.suffice/luna-baseline-v2/attempts/<task>-suffice/worker/events.live.jsonl`. Each JSONL event is one physical line. Actor patches, original tests, independent grader outputs, prompts, and raw usage remain preserved alongside those traces.

Operational category definitions:

- **Retrieved missing:** an identifiable relevant public artifact was absent from returned worker observations. Absence is not evidence that the model could not infer the behavior otherwise.
- **Retrieved overlooked / not preserved:** relevant code or a requirement was demonstrably available before the edit, but the submitted patch does not preserve the behavior. This label does not assert that the model mentally ignored it.
- **Incorrect invariant:** the submitted code encodes a testably false behavioral condition. The category describes the patch, not a claim about an internal belief.
- **Implementation:** an observed defect in the submitted change whose internal decision cause cannot be established from the trace.

No listed failure is confidently attributable solely to missing retrieval. Important public code was already returned in all eight. Missing README/type reads in i03 are an observed retrieval gap, but the public task and original implementation also supplied relevant evidence, so labeling the whole failure as missing retrieval would overstate the trace.

These observations support testing whether a compact executable counterexample changes a decision. They do not establish that more retrieved text, semantic references, a planner, or any particular evidence packet would have prevented the failures. A subsequent experiment using these tasks is development reuse, and its generated probes must not be derived from private assertions while being represented as public-only evidence.

The i03 diagnostic is separate under `.suffice/luna-baseline-v2/diagnostics/i03-no-arraylike/`. Only the disputed array-like assertion was omitted in newly reconstructed workspaces. The original still fails the earlier mapper-rejection check, the Luna patch reaches and fails the later immediate-settlement assertion, and the reference passes. The general Iterable type versus Array.from equivalence merits documentation clarity; root's fresh original-issue audit confirmed that the issue itself explicitly requests both behaviors. Primary grades remain unchanged.
