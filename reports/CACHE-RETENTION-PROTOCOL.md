# Cache retention protocol v1

Question: Does replacing old read-only tool-result bodies reduce total provider-estimated cost enough to offset cache disruption without losing task completion?

Arms share GPT-6.1 Sol, low effort, native Pi codemode, AST navigation, work_state, identical tools/prompt, per-attempt $0.25 observed cost ceiling, 18 generation ceiling and 240s wall timeout. Append keeps all context. Retention triggers above 18,000 serialized characters; keeps all user/assistant messages, all call/result associations, first codemode result, two recent codemode results and every mutation/test/state/recovery result. Only older verified read-only batch result bodies larger than 1,200 characters become exact recoverable archive references. No model summary or auxiliary inference. Model reasoning remains intact. Work-state metadata carries requirements, unresolved issues, edits, test revision and freshness. Replaced sources explicitly warn of possible staleness after edits. evidence_read recovers 8,000-character pages; reread current source for edits.

Fresh real upstream tasks: node-semver issue 703 OR-union subset coverage and PR 878 open-tilde prerelease behavior. Fixed source snapshots and pinned upstream reference files are checked against independent hidden acceptance matrices and seven adapted visible upstream fixture groups. Reference fixes must pass both and original code must fail acceptance. No hidden acceptance diagnostics are exposed to agents. Only production JavaScript edits allowed. Tests/docs/metadata immutable; patch and baseline integrity checked.

Screening runs union-subset once per arm before scored launch. Scored schedule: two tasks, two repetitions, both arms; order rotates by task/repetition. The union task is screened and reused; tilde is untouched by screening. Screening failures determine difficulty evidence, not score. Do not infer capability improvement when baseline all passes, or retention effectiveness when inactive. Archive/recovery and cache telemetry are distinct.

Stop before another attempt at $2.70 known campaign model cost or any unknown-cost attempt, 95 MiB fixture/run artifact guard, less than 1 GiB disk, or $3 total known API-equivalent budget. A completed provider response can overshoot a per-run ceiling; report this and unknown costs honestly. At most two planned screening plus eight scored attempts. All model calls, retries and failures count. Subscription billing is unknown; Pi estimates are API-equivalent, not actual billed charges. Codex engineering inference is outside benchmark accounting.

Concurrent parent/other campaigns can contend for provider throughput, local CPU and prompt cache. Stable cache warmth is uncontrolled. Small historical public tasks may be memorized. Two tasks cannot establish generality. Operational completion and independently acceptable patch are reported separately. Latency and local test compute are distinct from model usage.

Reproduce: node scripts/prepare-cache-retention.mjs; node --test tests/cache-retention.test.mjs; node scripts/cache-retention-experiment.mjs screen; inspect screen results; node scripts/cache-retention-experiment.mjs scored. Every phase writes immutable manifest and frozen source; completed attempts resume idempotently. Hidden process PID/log receipts under .suffice/cache-runs. Raw transcripts remain local ignored artifacts; do not commit/publish them.
