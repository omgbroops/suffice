## Why independently wrong V2 patches did not escalate

The original controller's trigger is an observed failure among configured checks.
All five V2 strict failures in the previous 15-issue campaign passed those public
checks. The independent grader's result is not available inside the worker or
controller. Therefore `adviceCalls`, repairs and takeovers correctly stayed zero.
The b02 grader caveat from that campaign remains unchanged; it is not clean
evidence of failure to satisfy the issue itself.

decomp v7's controller differs: v6 `checked` calls `harness_ok`, and v7 feeds the
one-bit hidden-test failure into later review/retry phases. Test contents can stay
sealed while their pass/fail still influences execution. That is useful for its
benchmark but is not the no-hidden-feedback workflow requested here.

## Low-overhead public verification

1. Map the actual issue clauses to a small explicit plan, retaining supporting public
   excerpts. Separate desired new behavior from documented compatibility. Do not
   invent extra acceptance rules to resemble an upstream patch.
2. Before trusting a reproducer, show that it fails on the unrepaired public source
   and passes a focused repair. Check that the test runner executes assertions;
   exit zero from an empty loader invocation is insufficient. Preserve controls.
3. After implementation, reuse relevant project checks and run the public reproducer
   once, under a small shared deadline. Keep evaluator scripts read-only. Report
   the covered clauses and any unverified remainder; passing is not a completeness
   or correctness certificate.
4. On a reproducible public contract failure, fund at most one bounded repair.
   Flexible uses the exact same model/effort. Efficient may add its existing short,
   tool-free Sol advice and bounded takeover within the same task allowance.
5. Distinguish missing dependencies, runner failures and provider failures from a
   semantic counterexample before paying for an escalation. The current generic
   check interface records errors but does not automatically classify all such
   infrastructure failures; this remains a limitation, not a claimed solved feature.

This adds deterministic work and only conditional inference. It does not require
an expert planner/critic on every task, hidden-test queries, or a model's ungrounded
self-assessment. The branch supplies the explicit plan and controller plumbing;
automatically deriving trustworthy contracts is outside this implementation.

This evaluation keeps model/effort and harness settings fixed within each stratum,
and separates deterministic checks from independent grading, consistent with
[OpenAI's evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices).
Single attempts on four easy issues are still descriptive evidence, not a population
estimate or a reliable causal estimate of a small cost difference.
