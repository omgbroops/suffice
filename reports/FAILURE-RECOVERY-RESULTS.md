# Failure recovery: provider-limited pilot

Implemented ordinary iterative repair versus deterministic validated checkpoints and rollback. The live comparison is inconclusive: the shared ChatGPT Subscription Sharing usage limit interrupted the first attempt and rejected the following three. No scored campaign ran and no live rollback activated. No efficiency or capability improvement is established.

| Pilot arm | Attempts | Operational successes | Independently accepted patches | Actual rollbacks |
|---|---:|---:|---:|---:|
| Normal iterative repair | 2 | 0 | 1 | 0 |
| Checkpoint/rollback | 2 | 0 | 0 | 0 |

The first normal attempt repaired the BOM-boundary task in six tool generations; its next generation failed at the provider limit. The resulting production patch passed three hidden behavioral tests, seven visible regressions, and 297 original upstream assertions. It remains an operational failure. The other three attempts made zero tool calls and changed no files. These provider rejections are not evidence of difficult coding failures or inferior recovery. The unattempted third task is empty block-scalar outdent.

Known API-equivalent inference is **at least $0.0437584** across all four attempts: 13,842 input, 1,290 output, 31,744 cache-read tokens. Every attempt has unknown complete cost telemetry. Immediate rejections have zero recorded usage, which is a lower bound rather than a confirmed zero bill. No API-key fallback, helper inference, or further subscription calls were made. Engineering-agent costs are outside these figures. All actual assistant model IDs were gpt-6.1-sol; sessions requested low effort.

The frozen policy requires two distinct edited source states with failed executable visible checks before restoring the last passing full-regression checkpoint. An unchanged failing check, initial baseline reproducer, infrastructure failure, or generated passing case cannot promote or trigger a checkpoint. It restores only the owned production allowlist, retains all failed source states/diagnostics/costs, reports rejected approaches, and marks tests stale after restoration. Latest-check freshness records its kind; partial cases never certify a full-regression checkpoint. Passing visible regressions does not prove bug correctness. A rollback may discard useful unvalidated partial edits; their full source snapshots remain available in failure evidence.

Validation: **6/6 focused policy/integration tests passed**, including real local failing executable checks followed by restoration and fresh passing revalidation. This offline activation verifies the mechanism, not live model recovery. Broader existing harness checks passed 85/86; the unrelated synthetic retry-idempotency reference patch fails because CRLF workspace source does not match LF JSON replacement text. A temporary LF-normalized copy matched both replacements and passed original-failure/reference-repair/visible verification. No existing source or fixture was changed to fix that pre-existing issue.

All three fresh historical real-repository tasks were independently validated: baseline acceptance fails, pinned upstream reference acceptance passes, visible regressions pass before/after, and original upstream core checks pass before/after (297, 286, and 305 assertions). They are distinct from the main YAML campaign. Historical fixes may exist in training; BOM and merge tasks are screening-exposed, and this is not an untouched holdout study. Fixture docs/dist/fuzz/stress assets were excluded; small original archives/extractions are retained locally.

Frozen input, frozen copy, baseline, patch and immutable-file audits all passed. Thirty frozen inputs remain unchanged. Local campaign artifacts occupy 32,079,556 bytes (30.6 MiB), with over 9.6 GiB free at verification; new report/source artifacts add under 0.2 MiB. Transcript literal tool paths were inside the workspace; no hidden-grader or outside path was observed. Raw transcripts remain local under ignored .suffice/, separate from shareable reports. Concurrent campaigns share the provider/machine, so latency and cache figures cannot support causal comparisons.

The v1 provider-stop regex missed the exact usage-limit wording and unnecessarily launched three more bounded rejected calls. That defect and the original frozen implementation remain preserved. Separate, unscored v2 files use the existing robust provider classifier and scoped custom search reads. V2 syntax checks passed; v2 has not been live evaluated. See [amendment](../docs/RECOVERY-V2-AMENDMENT.md). No current frozen inputs were edited.

Recommendation: retain the tested recovery mechanism as an experimental option, not a demonstrated capability improvement. Resume only after quota availability on a new, untouched difficult corpus with genuine baseline coding failures and actual rollback activation; use v2 safety corrections and a newly frozen manifest. Do not rank arms from this interrupted pilot.
