# Suffice versus native Codex: Sol Extra High review

The complete requested comparison ran on Sonion: ten previously exposed historical GitHub issues, twenty new actor sessions, both harnesses on GPT-6.1 Sol xhigh. Native Codex CLI 0.163.0 used its own prompts, native code execution, tools and compaction. Suffice used a separately frozen general-v1 copy with only effort literals and the cost ceiling changed. No new optimization, routing, memory policy, verification stage or engineering subagent was added. Original general-v1 source and previous benchmark artifacts remain unchanged.

**Observed efficiency:** Suffice cost 13.12% less per attempt and 18.56% less at the median. It was cheaper on 8/10 pairs. The scored inference totals were $1.9667916 versus $2.2638532. Every one of the 274 response-level usage records reconciled with the actor totals; all twenty final attempt costs are known. There were no operational failures, budget stops or unmatched response costs in this matched run.

**Quality needs a qualification:** frozen native/private checks accepted 10/10 Suffice patches and 9/10 Codex patches. The only rejection is q02: Codex broadened a documented completion event, changed its test and README, and failed the restored original event test while passing all four issue-specific checks. The issue itself suggests that event broadening. A compatible solution exists and Suffice found one, but the public signals conflict. This is a contract-sensitive divergence, not an undisputed capability failure. Q02-CONTRACT-REVIEW.md explains the evidence and qualifies earlier claims about the same Pi rejection. Frozen scores and every task's costs are retained.

The separately labeled nine-pair sensitivity excludes q02 only to assess that ambiguity: both harnesses pass 9/9, with Suffice still 12.11% cheaper per attempt ($0.191833 versus $0.218263). This is a post-outcome sensitivity, not a new confirmatory cohort. It does not erase q02 or replace the main ledger. No capability advantage is established by the current sample.

**The time tradeoff:** mean actor time was 269.8s versus 206.3s, 30.8% longer for Suffice. Medians were 242.1s versus 227.4s. Latency includes each actor's commands and retries, excludes independent grading, and reflects some overlap between independent pairs. The clients retain their own transport behavior; backend/account equality is not independently established. These times are descriptive, not a pure causal measure of harness speed.

**Where the money went:** Suffice processed 3,171,645 input tokens versus 5,624,870, a 43.6% reduction. Fresh input was almost unchanged (453,309 versus 450,598); cached input was 2,718,336 versus 5,174,272. Output was 78,834 versus 84,523, 6.7% lower. Reasoning output, already included in those totals, was 45,548 versus 44,722.

The cost components were fresh input $0.906618 / $0.901196, cache reads $0.271834 / $0.517427, and output $0.788340 / $0.845230 (Suffice / Codex). About 82.7% of the net monetary difference is attributable arithmetically to the cache-read component. This is accounting attribution, not an ablation proving navigation or prompt length caused the gain. Lower total input volume did not translate proportionally into lower spending because most removed input was cached.

Suffice used 126 model responses versus 148. Model-visible calls were 116 versus 138; native command and Suffice primitive counts have different observability and remain separate. Native response counts come from deduplicated token_usage_record receipts, not its single logical turn.completed event. Reasoning ciphertext length was never used as a token estimate.

**Wins and losses:** the full per-issue table is in RESULTS.md and attempts.csv. Suffice was cheaper on s01, s03, i01, i02, i03, i04, q01 and q02. Codex was cheaper on q04 and s02. The q04 Suffice attempt made more model responses and took substantially longer. The traces establish additional work, but this experiment does not isolate whether tools, reasoning variability or another harness behavior caused it.

**Independent supplementary checks:** the same established probes were replayed for both actors on s01, i04, q04 and q02, with baseline and reference controls. All actor probes passed except Codex's q02 completion-event probe, which has the same contract qualification as its primary rejection. Both actors preserve the reserved-event boundary, avoid the fastq reentrant-pause hang, update dormant cross-copy computed values and wake the last size waiter. The upstream fastq reference still hangs on reentrant pause, as already known; reference correctness is not assumed beyond its supported checks. No extra concrete regression was found in this bounded review. No model was rerun and no hidden feedback reached an actor.

**Uncertainty:** one attempt per configuration and issue, six correlated repositories, reused issues and public solution hints limit generalization. A paired-task resampling sensitivity puts the observed cost saving between -1.2% and 25.0% at its 2.5/97.5 percentiles; this crosses zero and is not a population confidence claim. The results are promising cohort-level efficiency evidence, not proof of global superiority. The tasks largely hit a correctness ceiling and do not discriminate difficult engineering capability. Neither Astra nor Luna nor a full Coding Agent Index run was performed here.

**All-attempt accounting:** the matched twenty attempts cost $4.2306448 API-equivalent inference. An earlier native Codex issue attempt was interrupted when the background WSL job terminated; six completed responses cost $0.1207664 and an in-flight response has unknown cost. Two completed compatibility sessions add $0.0227268; denied setup requests have no recorded usage. The known overall total is at least $4.374138, with an unknown full total. The interrupted task is operational, not a coding failure; its trace and partial patch are preserved in v1. Inclusive issue cost bounds and setup rows are in extra-attempt-accounting.json and metrics.json. The headline matched-run estimates do not silently zero those costs.

These amounts use one pinned API-equivalent price table for both clients, including cache and context tiers. They are not subscription cash charges and exclude the engineering parent's inference, power, machine rental and other project work. There are no new upstream PRs or maintainer communications.

**Smallest justified decision:** keep the frozen lean baseline and the native Codex adapter as comparison baselines. The evidence supports a modest observed cost advantage here, with a runtime tradeoff and no established capability lead. The next useful validation would use fresh, unambiguous contracts and repeated paired attempts; no new harness mechanism or additional model campaign is automatically started. INDEX-METHOD.md describes the separate, much larger 303-task / three-attempt benchmark protocol needed for a Coding Agent Index-style result. The supplied graph uses our actual cohort and shows the disputed-case sensitivity explicitly.
