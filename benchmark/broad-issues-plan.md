# Proposed next campaign: 15 independent open-source issues

This is preparation for the user's requested broader follow-up, not a dispatched campaign or a frozen manifest. Finish the six-attempt effort comparison before selecting the v2 configuration. Do not change the harness in response to broader-campaign outcomes.

## Cohort

Select 15 new historical issues across at least 10 repositories, at most two issues from one repository. Cover different behaviors such as parsing, asynchronous lifecycle, CLI compatibility, validation, networking, and stateful APIs. Include multi-file and compatibility-sensitive work where the issue warrants it. Broader project coverage does not by itself establish language coverage.

Exclude all issues already used in the packet, pipeline, effort, and field campaigns. The existing Sonion field pool has 16 prepared issues across nine repositories, all now historically exposed; it is a development pool, not a fresh evaluation cohort. Record the full exclusion inventory before selection. Public historical issues can still have appeared in model training data; fresh here means unused by our evaluation/development, not guaranteed training-unseen.

Each candidate needs a pinned pre-fix revision, public issue prompt, working dependencies, public project checks, an isolated reference patch, and independent acceptance cases justified by public requirements/API contracts. Grade the original source and reference before any actor inference: original public checks must match a documented baseline, acceptance must fail for the bug, and the reference must pass. Reject nondiscriminating or broken candidates before outcomes; freeze a reserve order before dispatch rather than substituting based on model success.

## Systems and selection

Compare native Codex GPT-6.1-Sol Low, original Suffice v1 GPT-6.1-Sol Low without routing, and a frozen opt-in v2 policy: 45 attempts for a single pass. Preserve the original interfaces, model/effort identities, and complete orchestration costs.

A fourth, same-model control (original Suffice v1 Luna High) would distinguish worker-price effects from v2 harness effects on the broader cohort. Including it makes 60 attempts; decide and freeze that scope before dispatch, never add it after seeing outcomes.

Use the effort comparison to choose an explicitly experimental v2 effort setting. Treat three-task differences as preliminary; do not claim they establish equal quality. Keep any advice, repair, takeover, or fleet behavior declared and budgeted. Record actual activation instead of attributing results to enabled but unused mechanisms.

## Controls and accounting

Freeze local and remote source hashes, prompts, task revisions, dependency/runtime identities, independent graders, arm schedules, model catalogs, and limits before dispatch. Use isolated actor repositories with only their base commit reachable; keep private tests/reference patches outside the actor boundary. Use fresh actor/session state for every attempt. Keep total concurrency fixed and counterbalance system order across issues. Observe cache usage; do not claim cache equivalence unless it is controlled.

For continuity, a possible starting allowance is $0.25 API-equivalent, 300 seconds, 40 responses, 160 calls, and 4 GiB process-tree RSS per attempt, shared across all v2 stages. These limits and the campaign ceiling must be finalized before dispatch; one response can overshoot a dollar limit. Under these nominal limits, 45 attempts reserve $11.25 before response overshoot. Preparation/control time is separate from actor time.

The optional fourth arm increases that nominal reservation to $15 for 60 attempts. This draft does not dispatch either schedule.

Retain every attempt, failed/partial patch, timeout, unknown cost, raw usage receipt and grading result. Do not rerun or tune after seeing acceptance feedback. Do not discard an operational failure from the denominator. If accounting/isolation fails, preserve evidence and stop new dispatch. Any infrastructure correction requires a separately identified campaign amendment.

## Report

Report independently accepted and budget-eligible tasks, all-cost-per-accepted-task including failed spending, total cost, unknown costs, mean/median/tail latency, model responses, tool calls, fresh/cache/output/reasoning tokens, peak RSS, and actual policy stages. Include per-issue paired outcomes and operational failures, not just aggregate savings. Distinguish actor latency from end-to-end orchestration/grading time. Hash-verify remote/local harness parity and downloaded evidence.

Fifteen issues is a broader pilot, not a precise estimate of general accuracy or proof that individual optimizations help. Separate model-price effects from harness efficiency, and report how many repositories, task types, languages, and difficulty levels were actually covered. Further repetitions or feature ablations should be separately predeclared.
