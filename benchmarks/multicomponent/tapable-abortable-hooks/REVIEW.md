# Authored staged feature candidate

This is a separate calibration feature phase. It is not part of the existing frozen repair campaign and no inference has been run for this task. `scopeTier: 3` describes the staged engineering hypothesis; it does not certify natural long-horizon exposure, context pressure, compaction, persistence or delegation benefit.

The complete Tapable v2.2.1 repository is pinned at `a0a7b26224557bd8bb09b97e0126b7dbda9f8e6a`. The 98,543-byte tarball contains 43 regular files totaling 457,348 bytes. Baseline source is pristine upstream. The authored known reference adds only the documented opt-in JavaScript feature in four existing production modules; no upstream issue or injected bug is claimed. No runtime dependencies are installed or vendored.

The bounded feature adds AbortSignal invocation to AsyncSeriesHook and AsyncParallelHook. API/cache integration, shared generated adapters and lifecycle, ordered continuation, parallel dispatch and plugin-pipeline integration are checked separately. Bail, waterfall, looping and synchronous Hook kinds do not gain the feature. Valid native signals, non-context taps/interceptors and nonthrowing terminal observers define the supported new API scope. TypeScript declarations are deliberately outside this JavaScript task.

The actor's actual test tool runs all seven public cases: four existing smoke checks and three new-feature checks. `taskType: feature` therefore expects baseline smoke **4/4**, public feature **0/3**, combined visible **4/7**, hidden **0/16**. An entirely green baseline visible suite would hide feature feedback from this tool interface. The reference passes public smoke **4/4**, feature **3/3**, combined visible **7/7**, hidden **16/16**.

The hidden tests use real exported Hook instances and generated execution. They inspect argument/error identity, unbound receivers, callback outcomes, gate-controlled launch order, listener counts, observer order, in-flight registration snapshots and reusable cross-Hook pipelines. They do not inspect generated function text or require the solver to match the reference's module/edit shape. A valid centralized alternative can pass, and a quick solve would be evidence against the long-task hypothesis for this candidate.

Four reference ablations preserve old smoke behavior but fail both their independently mapped stage and the plugin pipeline: omitted cache invalidation (13/16 hidden pass), omitted listener cleanup (10/16), ordered dispatch replaced by parallel (12/16), parallel replaced by ordered (11/16). Every hidden case executes, with zero cancellations. These are behavioral sensitivity checks of this reference, not proof that every valid implementation must change four files.

Preparation: run `python scripts/prepare-tapable-feature.py` from the worktree root. It checks the pinned tarball SHA-256, bounded download/extraction, complete source inventory and reference patch preimages. It copies all upstream files, writes exact public tests and prompt to both workspaces, and records original/reference hashes. `private/reference-patches.json` is evaluator-only reproduction evidence, never actor input. The task-local `.gitattributes` preserves source and receipt bytes when the directory is copied into another benchmark dataset on Windows.

Validation: run `node scripts/validate-tapable-feature.mjs` with normal Suffice dependencies available. In an isolated worktree, `SUFFICE_HARNESS_MODULE` may point to another checkout's existing `src/workspace.mjs`, read-only. This receipt used the root checkout's permission-restricted native Node runner. Graded code has read access only to its workspace and the test file; tests need no network, filesystem writes, subprocesses, package scripts or external service. A few `setImmediate` calls flush actual unhandled-rejection reporting; they do not add workload delay.

`task.json`, `source.json` and `validation.json` contain the contract, exact test/requirement map, stage cases, source hashes, outcomes and limitations. Resolve metadata paths against the directory containing `task.json`. Existing smoke, public feature and hidden paths are separate; the actor-visible tool path remains `actor/tests/visible.test.mjs`.
