Implement opt-in abortable invocation for the JavaScript AsyncSeriesHook and AsyncParallelHook classes in the complete pinned Tapable v2.2.1 repository under src/. This is an authored new-feature task with an authored known reference, not an upstream historical bug. The existing public module is src/lib/index.js.

Add callAsyncWithSignal(signal, ...declaredHookArguments, callback) and promiseWithSignal(signal, ...declaredHookArguments) to instances of these two classes only. Other Hook kinds, including synchronous, bail, waterfall and loop hooks, must not gain these methods. Preserve existing call/callAsync/promise and registration behavior. New methods must participate in normal lazy compilation and be invalidated independently when tap or interceptor registration changes; warming one entry point must not make another entry point stale.

Inputs and invocation: signal is a valid native AbortSignal and is mandatory; invalid/duck-typed signal validation is outside this task. Hook argument names for the new methods are distinct ordinary JavaScript identifiers that do not start with an underscore. Forward declared arguments unchanged. Invoke taps and the terminal callback as unbound functions, following ordinary JavaScript receiver rules; strict functions observe undefined this. Support tap, tapAsync and tapPromise. Ignore tap result values because these two Hook kinds have no result. Only tapPromise return values are observed as promises; synchronous and callback-tap return values remain ignored, as in their existing invocation conventions. A successful terminal callback receives zero arguments; a failure or cancellation receives exactly one argument. promiseWithSignal resolves undefined on success and rejects with the original error/reason on failure or cancellation, preserving identity and falsy values.

Timing and completion: invocation starts synchronously and proceeds until asynchronous work is pending. An already-aborted signal starts no taps and runs no call/tap interceptors; callback cancellation is synchronous, and the promise is rejected normally. Cancellation during an active invocation is delivered synchronously within abort dispatch for callback mode. The first terminal event observed by the invocation wins; a later abort cannot override an already completed success/error, and a later completion/error cannot override cancellation. Preserve signal.reason exactly, including null, false and zero. Native promises retain normal microtask delivery.

Tap adapters: a synchronous throw fails the invocation with that exact thrown value. Callback taps use the existing error-first convention: a truthy first callback argument is failure, otherwise success. Honor only each tap's first callback completion; duplicate callbacks and a throw after that tap already called back cannot settle again, rerun successors or corrupt the parallel join. Promise taps must return a promise/thenable; observe fulfillment or rejection. If a promise tap synchronously aborts and returns a rejected promise, or an already-started promise tap rejects after cancellation, observe that rejection so the new APIs cause no unhandled rejection. Cancellation does not terminate underlying work; late callbacks and promise-tap rejections remain safely observed and cannot change the terminal outcome.

Series semantics: start taps in normal registration/stage order, waiting for each to complete before starting its successor. Failure or cancellation prevents remaining successors from starting. Parallel semantics: eagerly launch taps in registration/stage order without waiting for earlier asynchronous taps; successful completion waits for every started tap. If a tap aborts synchronously during dispatch, do not launch later taps. Already-started work can finish after cancellation and must be ignored safely.

Lifecycle, interception and reuse: attach one abort listener per active invocation and remove that invocation's listener immediately on success, failure or cancellation. An already-aborted invocation adds no listener. Remove the listener before terminal interceptor notification, and run terminal interceptors before the terminal callback/promise completion. Preserve non-context, nonthrowing register/call/tap/done/error interceptors: call before taps, tap before each started tap, done once on success, error once with the original failure/cancellation reason. Pre-aborted invocations still notify error interceptors once. Cancellation from a call/tap interceptor also prevents subsequent starts. Throwing terminal callbacks/interceptors and deprecated context-enabled taps/interceptors are explicitly outside the new API contract; their existing API behavior must remain unchanged. Concurrent invocations isolate listeners and terminal state even when sharing a signal. Each invocation snapshots its registered tap functions and interception metadata; registering taps/interceptors while one is active affects later invocations, including after recompilation, without changing that active invocation. After an aborted plugin pipeline composing series and parallel hooks, fresh signals and newly registered taps must work correctly on reuse.

Only existing production files src/lib/Hook.js, src/lib/HookCodeFactory.js, src/lib/AsyncSeriesHook.js and src/lib/AsyncParallelHook.js may be edited.
