# V10 versus native Codex: 15-task protocol

Compare the existing v10 agent (Pi, Luna high, Sol low independent tests/arbitration, Sol high selective takeover) with native Codex using `gpt-6.1-sol` at high effort. This compares whole agents with different model-routing strategies, not just their harnesses at identical compute. The original v10 implementation remains unchanged.

The native arm uses the desktop-bundled `codex-cli 0.162.0-alpha.17.2`, whose binary/catalog and successful model/tool canaries are recorded. The older CLI on PATH does not offer these models and is never substituted. This is a single-agent native CLI baseline: delegation, unrelated plugins, MCP, memories, hooks and web/browser features are disabled; user configuration, exec-policy rules and automatic project documents are ignored. Native retains its system instructions, shell/apply_patch and required Code Mode host. Raw events use the [official non-interactive JSONL interface](https://learn.chatgpt.com/docs/non-interactive-mode). Shell network access remains available to both agents.

Both agents run with full host access in fresh canonical temporary Git repositories. Native workspace-write canaries were blocked by this Windows setup's read-only policy; that mode was not used for benchmark actors. The final permission choice is explicit in the frozen plan and receipts. Local execution is not an OS secrecy boundary; temporary repositories reduce accidental access to evaluator/source material in the project checkout.

## Cohort

Fifteen historical JavaScript/TypeScript repairs across six repositories, none of which was among the earlier four pilot tasks:

These are previously studied historical development replays from the repository's existing task banks. They are not unseen tasks or a general coding-agent leaderboard. Source versions, archive URLs/checksums, original tree hashes and public suites are preserved. No installation is needed; Node 24 runs the TypeScript sources directly. All fifteen original public suites pass (70 named tests).

## Execution and scoring

- One attempt per task and arm: 30 runs, with a seeded interleaved schedule and two concurrent lanes. Fresh input copies and sessions for every attempt.
- Same 600-second actor deadline. No practical dollar cutoff. V10 retains its existing per-stage 24-turn/80-tool and conservative context bounds; native uses its own loop. Common final verification/snapshot overhead is reported separately from actor latency.
- Identical public prompts and regression suites. Original tests, fixtures, docs and package metadata are immutable. The wrapper restores them before final public checks and again before sealing, including on actor failures; violations remain recorded.
- Existing independent acceptance suites and reference procedures are frozen by hash before execution. The freeze's digest is bound into execution-started and execution-complete records. Graders and fixed references load/run only after all 30 actors are terminal.
- Each grader must reject the broken original through a real assertion failure or a reviewed production exception directly violating the public contract, and accept the pinned reference; both original and reference public regressions must pass. The complete expected suite must execute without skipped/cancelled tests or infrastructure errors. Invalid task evaluation stays ungraded. Actor scoring uses fresh copies of verified sealed snapshots. An unverified grading subprocess stays ungraded rather than receiving an invented verdict.
- Private outcomes never enter either actor/controller, fund a repair or cause a retry. Public-spec tests generated by v10 remain ordinary development checks, with no independent-grader access.
- Unknown usage does not stop the remaining uncapped attempts. Unknown costs remain null with any known floor. Record source acceptance separately from completion within operational controls and without protection violations.

Report independent passes, valid completions, paired wins/losses/ties, failures, ungraded tasks, repairs/takeovers, latency and estimated cost per accepted task. Use the same pinned Pi base input/cache/output rates for both arms and keep raw tokens. Native aggregate usage cannot establish per-request long-context surcharges or the inclusion semantics of positive cache writes; disclose these limits and retain unknown pricing rather than invent an exact invoice. Canary/preflight usage is separate from the 30 scheduled attempts.

## Recorded scoring correction

The original frozen grading driver required the literal error code `ERR_ASSERTION` when validating broken baselines. After the 30 actors closed, this left cookie-173 ungraded: its serializer throws on a valid leading-dot domain before `assert.equal` can execute. A fresh reviewer inspected only the frozen test, public contract and baseline/reference receipts, then confirmed the intended production defect. Both original/reference public suites and reference acceptance passed.

The original driver, assertions, freeze and initial `grades.json`/`summary.json` remain intact. The separate `scripts/v10-native-revalidate.mjs` binds the reviewed rule and original artifact hashes before scoring the two previously ungraded saved cookie snapshots. It changes none of the other 28 grades, starts no coding actors, and emits `grades.final.json`, `reference-validation.final.json`, `summary.final.json` and supplemental receipts. These final files are authoritative for this report. Its case-specific correction command is:

```powershell
node scripts/v10-native-revalidate.mjs <closed-plan-dir> <cookie-review.json>
```

This correction is explicit rather than retroactively changing the frozen runtime. The archived decision includes the review text, matching baseline log hash, reference evidence, correction script hash and completion hashes. The reviewed baseline-validation rule was expanded after execution; this part of scoring was not wholly prespecified.
