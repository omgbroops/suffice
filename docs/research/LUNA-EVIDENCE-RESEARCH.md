# Evidence for a bounded Luna experiment

Research date: 2026-10-15. Research only; no harness changes, model calls, new agent deployments, package installs, tests, builds, or campaign changes were performed. This note is outside actor workspaces. It proposes work only after the frozen campaign results are complete and reviewed.

## Decision

The literature justifies a hypothesis about obtaining better evidence at an important decision, not a promise that GPT-6 Luna can match stronger Codex models. The smallest candidate is a **single, bounded pre-edit probe of an uncertain public behavior or preservation contract**, using the existing worker and tools. Do not add a planner, reviewer, evidence ledger, retention policy, learned controller, or semantic navigation service to that experiment.

First inspect observed Luna coding failures against valid independent contracts. If the failures do not show a recurring mistaken behavioral assumption that such a probe could distinguish, do not run this candidate. Fixing evaluator defects is benchmark repair, not an agent capability improvement.

## Verified papers

The sources below are the papers themselves, not generated web summaries. Full-text author versions were read in arXiv HTML. PatchPilot's publication identity was also checked against the official ICML proceedings page; the proceedings PDF endpoint was inaccessible through the web tool, so byte equivalence with that PDF is not claimed.

### SWE-RPG

[SWE-RPG, arXiv:2608.09072v1](https://arxiv.org/html/2608.09072v1), sections 3–5 and Limitations.

The quoted scale is correct: 163 tasks, 31 Python/Java repositories, 113 bugs and 50 features. Its 24.5–46.0% figure describes **all agent runs** assigned requirement failure, not the fraction of failed runs. It reports a 31.5% mean resolve rate across three scaffolds and six backends, with two runs per pairing/task. Requirements and plans are reconstructed using issue/repository/PR evidence, LLM assistance, validation, and human review. A judge retrospectively assigns unsuccessful runs to the earliest deviating stage; agreement with human consensus was 46/50 sampled failures. This supports investigating overlooked constraints, especially interfaces and data semantics. It does not experimentally establish that a clarification prompt, pre-edit checklist, or additional planning improves performance. Retrospective attribution is not causal attribution. Its language coverage, selected tasks, reconstructed references, and judge dependence limit transfer to Suffice's JavaScript/TypeScript tasks. It contains no Luna-versus-current-Codex experiment.

### PatchPilot

[Official ICML 2025 publication](https://proceedings.mlr.press/v267/li25cf.html); [full text, arXiv:2502.02747v2](https://arxiv.org/html/2502.02747v2), sections 3–5.

Its fixed workflow combines reproduction, localization, planned patch generation, validation, and refinement. Reproduction supplies execution outputs/coverage; validation includes existing functionality tests; failed candidates can trigger refinement or renewed localization. With Claude 3.5 Sonnet, it reports 45.33% at $0.97/instance on SWE-bench Lite and 53.60% at $0.99 on Verified. Baseline results largely come from published submissions rather than a controlled, budget-matched rerun. The ablation is especially relevant: improved localization/generation scored 38.7%; PoC-only selection fell to 37.0%; adding functionality tests reached 41.67%; refinement reached 45.33%. These are bundled workflow results, not evidence for an isolated pre-edit probe or Luna improvement. The stability subset was selected from tasks previously solved by both methods. Formal verification covered eleven Lite patches, not all patches or all program behavior. Reported historical API costs do not predict current Suffice costs.

### Thinking Longer, Not Larger

[arXiv:2503.23803v2](https://arxiv.org/html/2503.23803v2), sections 2, 3.2, 3.4, and 5.

SWE-Reasoner combines supervised training of Qwen2.5-Coder-32B on filtered development trajectories with external search. Dev-Search samples repository-understanding and fault-localization candidates, prunes them with a trained process reward model, executes reproduction/regression checks, and uses a trained outcome reward model for final ranking. The trained model scores 37.6% on 500 SWE-bench Verified tasks; external search at generation budget eight reaches 46.0%. External-search analyses use a random 100-task subset. Generation budget is not a matched dollar, token, or latency budget. The paper itself reports that execution-only selection can deteriorate and that greater search can fail to help the hardest bucket. The result is not achieved by prompting an unchanged small model to think longer, nor by a small harness feature alone. Training, reward models, search, verification, different model/scaffold pairings, and inference overhead prevent a direct Luna-to-Codex extrapolation. It motivates an equal-allowance control, not immediate training or branching search.

## Semantic references versus the current navigator

The current navigator parses with Acorn, strips strippable TypeScript first, stores declarations/import syntax, and finds references by equality with the final component of a name. It does not resolve lexical bindings or imports. Thus two unrelated `release` identifiers can be returned together; an import alias can have a different spelling from its declaration. This conclusion follows from source inspection, not an executed failure demonstration. The implementation advertises candidate references, exposes parse failures, hashes cached source, and refreshes after edits. Its supported extension filter excludes JSX/TSX. Adding another AST traversal does not itself add semantic resolution.

[TypeScript's compiler guide](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API#type-checker-apis) distinguishes syntax nodes from resolved symbols/types and documents `program.getTypeChecker()` and `getSymbolAtLocation`. For interactive reference queries, the language-service interface exposes position-based definitions and `findReferences(fileName, position)` ([official TypeScript v5.9.3 interface](https://raw.githubusercontent.com/microsoft/TypeScript/v5.9.3/src/services/types.ts)). This versioned source is an API reference, not a claim about an installed dependency or the latest release.

[Microsoft's language-service design](https://github.com/microsoft/TypeScript/wiki/Using-the-Language-Service-API#design-goals) explicitly favors on-demand computation, host-managed project files/versions, and incremental snapshots. An implementation would still need correct project options, module resolution, dependency/type visibility, and refresh after edits. Demand-driven queries do not guarantee constant startup cost or a complete runtime call graph.

[The official LSP references specification](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/language/references.md) defines project-wide references for a symbol at a document position, returning locations and optionally declarations. LSP is the transport contract; the chosen language server supplies resolution. It does not make dynamic JavaScript behavior or missing dependencies statically knowable.

If later traces show unresolved aliases/shadowing are a material cause, test semantic references separately: reuse an existing project service where possible; request one exact path/position; return bounded locations, project/config identity, source hashes and spans, truncation/incomplete status; invalidate stale positions. Preserve an explicit lexical fallback. Measure cold initialization, warm queries, peak memory, output tokens, and changed decisions. Do not build a repository-wide graph or silently treat an unresolved result as proof that no references exist. Do not combine this intervention with the probe experiment.

## Candidate protocol after the frozen results

This is a proposed protocol, not authorization to start another campaign.

1. **Development audit.** Use completed failures to identify one mechanism, such as a worker modifying stateful behavior after observing only a one-shot example. Verify the contract using public task/repository evidence and independent tests. Reject requirements inferred solely from an arbitrary historical patch or unsupported grader assertion. Previously failed tasks may tune the mechanism only; label all reuse as development.
2. **One intervention.** A short instruction in the existing worker asks for at most one discriminating, executable public-API probe before the first production edit when a specific behavioral uncertainty matters. The probe should cover that uncertainty plus an adjacent preservation case, such as a second call on the same object or malformed-input rejection. Record the assumption, expected distinction, actual result, and resulting edit decision in the existing trace. Skip with a stated reason when there is no discriminable uncertainty or the existing evidence already resolves it. No extra planner request, worker, scoring model, or new state infrastructure.
3. **Freeze A/B/C.** A is unchanged cheap Luna baseline at its existing allowance. B is the same model/effort/tools plus the bounded evidence instruction and a preregistered modest allowance increment. C is unchanged ordinary Luna execution with exactly B's allowance, without the evidence instruction. B versus C tests allocation to evidence; A versus C tests extra allowance. Keep B/C equal in inference ceiling, replies, calls, and wall time; report actual consumption, not just caps. Choose numeric allowances from development overhead before any confirmatory outcome, not after scoring.
4. **Fresh confirmation.** Freeze a distinct, actor-unused cohort and independently authored acceptance/preservation contracts before runs. Separate development and confirmation by issue and preferably repository; disclose possible public training exposure. Use repeated paired attempts and rotate order. Freeze source, dependencies, prompt, hashes, model/effort/catalog pricing, environment, tests, and schedule. Hold private/reference data outside the actor namespace; reconstruct patches against original tests. No hidden feedback repair loop, failed-attempt replacement, or outcome-driven task removal.
5. **Activation and accounting.** Report scheduled/attempted/completed/accepted/accepted-within-budget separately. For B count eligible uncertainties, actual pre-edit probes, valid discriminating probes, preserved cases checked, and decisions changed; distinguish attempted activity from useful evidence. Include setup/probe failures, deterministic time, latency, fresh/cache/output usage, all attempts, and unknown costs. Use existing traces and receipts; unknown cost stays unknown.
6. **Decision rule.** Before scoring, specify the acceptable accuracy margin and cost ceiling for the cheap-worker objective. Report paired successes/regressions and all-attempt cost per accepted completion, with uncertainty. A small development rescue is not a capability claim. If B fails to beat equal-allowance C, never activates usefully, or adds overhead without independently verified benefit, retain the baseline. Claim movement toward the stronger reference only if that reference is measured on the same heldout contracts under a separately disclosed budget; do not import a paper's leaderboard score.

The first concrete decision is whether completed Luna traces support this one uncertainty/probe mechanism at all. The research alone does not answer that question.
