# Revision-aware evidence record protocol

Snapshot: 37fb5e2. Engineering changes are isolated to experiment/evidence-record. The pinned Pi 1.2.0 and authentication/dependency junctions are reused, never reconfigured. No extra models, delegation, embeddings, pruning, rollback or reviewers are involved.

All repair actors are GPT-6.1 Sol low, with one shared TOTAL allowance per attempt: $0.12 known API-equivalent inference, 18 assistant generations, 100 tool calls, 180 seconds. Test design and repair share this allowance; there is no free model verification phase. Admission checks known cumulative usage between generations, so an in-flight generation can overshoot; an overshoot is never a within-budget success. Unknown totals are ineligible for that claim. Engineering-agent inference is excluded, not called total project spending.

A has native syntax navigation, ordinary reads/edits, regression testing, and (in screen/scored v1) bounded generic executable behavior checks. B adds the compact revision-aware requirement/evidence record. C adds explicit requirement/provenance-linked execution on the SAME executor and SHARED four-novel/eight-total check allowance. A/B may freely run novel checks; no fixed checkpoint suppresses them. All arms serialize mutations and test execution. Every actor has raw navigation; no source is pruned from history or replaced inside old messages.

Scored-v1 was frozen before larger-screen outcomes and never executed. Scored-v2 preserves its task/prompt/schedule/ceiling bytes and adds only model-invisible exact returned-source hashing and append-only durable live event logs. The unused freeze and telemetry amendment are retained.

Pilot v1 preceded the fair generic executor: A/B had public regression only and C had requirement checks. This pilot measures activation only and cannot isolate verification policy from added execution capability. Its frozen sources are preserved. Screen/scored v1 correct that confound; named moduleApi (all exports) and api (default export) are available equally. Record links can be superseded append-only.

Code captures source revisions, actual source-read hashes, check source hash, runner Node version, restricted fresh-process environment and start/end revisions. Source changes conservatively invalidate all test receipts. Read evidence remains traceable and becomes stale when its exact file changes or it races an edit. Modified test bytes also invalidate receipts. Record freshness eligibility is distinct from operational completion and independent correctness: it rejects stale linked evidence and unresolved links, but it does not establish semantic validity. An actor can complete while its record remains incomplete/stale, and this is reported, never silently upgraded.

The model supplies requirement wording, public provenance, links and unresolved questions. Those mappings and generated expected answers are hypotheses. Syntactically valid input and a failing baseline assertion do not prove a test valid. Generated checks are independently rerun against the public reference after the actor ends and inspected for task relevance; no reference/hidden diagnostics enter actor repair loops. Tests cannot write source or read outside the workspace and their own source; no explicit network or shell tool is exposed to actors. However Node 24.15 permission mode does not isolate networking, and arbitrary generated bodies could call fetch/import networking. Bodies and actor programs are audited for observed network/solution retrieval; absence of an exposed network tool is not a network sandbox.

Tasks are public historical repairs. Prompts are investigator-authored expanded contracts derived from the cited public fixes/docs, not untouched original issue prompts. Fix commit URLs are provenance, and no explicit network tool is provided. Generated Node bodies retain network capability, so observed use is audited rather than claiming isolation. Historical training contamination remains possible. Baseline failures and public-reference passes are validated before live work. The independently authored hidden final task checks and complete frozen public regression suite are identical across arms and always run after every attempt. These small authored regression suites are NOT the original upstream AVA/Mocha suites; the latter require unavailable dependencies and were not credited as passes.

Pilot: queue-drain A/B/C activation plus pmap-close A difficulty screening (4). Additional screen: substantially larger pmap-readahead A/B/C (3), using the revised fair executor. Scored: lru-duration and pmap-index, 2 matched repetitions each; emitter-once, 1 repetition; 15 attempts across three repositories. Scored inputs/schedule were frozen before the larger screen's result was known. Screened tasks do not enter scored results. Maximum total 22 attempts, $3 known repair inference, 100 MiB new artifacts and 1 GiB free disk floor, checked before admission. Failed/unknown attempts are retained.

Metrics distinguish operational success, independently accepted patch, known budget membership, within-budget successful completion, actual record reads/updates, freshness availability on reads (NOT proven semantic reuse), link reuse following an actual record read with no intervening source edit (still not semantic proof), generic/directed novel checks, exact repeat path/range/returned-text reads in scored-v2 (older pilot/screen counters are proxies), invalid or unresolved generated checks, check-discovered defects and subsequent edits, and unsupported completion. Abstentions/incomplete runs are unsuccessful. An all-pass control establishes no capability improvement. Equal ceilings are not equal realized costs; concurrent PC/provider load and cache warmth limit latency/cost causality.

Reproduce policy tests: `node --test tests/revision-evidence.test.mjs`.
Prepare pinned public sources: `node scripts/prepare-evidence.mjs`, then `node scripts/prepare-evidence-emitter.mjs`, then `node scripts/prepare-evidence-readahead.mjs` in a fresh checkout.
Campaign commands: `node scripts/evidence-experiment.mjs screen --freeze-only`, `node scripts/evidence-experiment.mjs scored --freeze-only`; run each with `--resume`. Do not rerun a frozen campaign under altered inputs; fresh experiment names require explicit runner changes and new manifests. The audit script reconstructs saved patches without any model calls.

Scope: each attempt starts with an empty in-memory record and persists append-only evidence to disk. This tests within-task tracking; it does not test loading after a process restart, warm cross-task reuse, or long-term memory. Whole-production-source invalidation is conservative. Results apply to this implementation/workload, not all persistent evidence architectures.

Freshness is a diagnostic, not an enforced termination gate. The runner never changes primary acceptance based on recordFreshnessEligible. It measures actors ending with stale/unresolved active links and whether later updates/checks follow warnings. A model may terminate despite insufficient recorded evidence; this implementation does not claim to know semantic completeness.
