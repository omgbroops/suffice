# Suffice v9 (experimental)

v9 is an opt-in native Codex runner for the existing Suffice research project. Its aim is strong coding performance at lower total model cost. It has not established that benefit. It retains useful mechanisms from the earlier versions without treating later versions as universally better.

The worker uses `gpt-6-luna` at high effort. An independent test writer uses `gpt-6.1-sol` at low effort, seeing the public request and original interface context, without the worker's patch. A failing generated assertion goes to a separate Sol arbiter, which must cite an exact public requirement. It may identify an implementation bug, propose one bounded assertion correction, or leave the assertion unresolved. Unresolved assertions remain unverified. They cannot grant acceptance or trigger paid repairs by themselves.

The controller allows one Luna repair by default, then one Sol takeover at high effort if verified public failures remain. After every change it scores all checkpoints against the same current tests and restores the best. Existing public failures outrank generated test gains. Tests, test configuration and package runner settings are restored before evaluation. Ignored implementation files are included in checkpoints so they cannot leak across rollback. No hidden evaluator or private verdict is an input to this controller.

This incorporates the handoff's independent-checker, false-alarm arbitration, checkpoint rollback and selective-rescue lessons. It omits always-on planning, ensembles and hint-specific policies pending ablations. Earlier Pi navigation/compact-output gains are preserved as historical evidence; changing native Codex's tools to imitate Pi would confound this comparison.

## Run

Requires Node 24+, Git and a logged-in native `codex` CLI. This path uses the CLI's normal authentication; it does not inspect or copy credentials. Earlier Pi and Claude commands still work independently.

Run `npm run v9:preflight` before launching paid work. It checks the installed CLI's model catalog without inference. Desktop model names and native CLI model availability may differ. The initial 2026-10-23 attempt was rejected because this CLI/account did not support `gpt-6.1-sol`; all subsequent attempts stopped with cost unknown. See the [pilot report](../reports/V9-CODEX-PILOT.md) for the preserved failure. No substitute model was used.

Supply JSON on stdin to `node scripts/v9-run.mjs`:

```json
{
  "workspace": "C:/work/my-task",
  "runDir": "C:/work/receipts/task-001",
  "prompt": "Implement the public feature specification here.",
  "strategy": "v9",
  "maxCostUsd": 0.5,
  "timeoutMs": 360000,
  "checks": [{"id": "tests", "command": ["node", "--test", "test/public.test.mjs"], "testsRequired": true}],
  "contextPaths": ["src/interface.mjs"],
  "protectedPaths": ["custom-test-settings.json"]
}
```

The workspace must be a standalone task Git root. Receipts must be outside it and use a fresh run directory. Original tests must already be present. Optional `contextPaths` expose bounded original interface text to the independent writer. `protectedPaths` declares project-specific check configuration in addition to automatic protection. Mixed manifests such as `pyproject.toml` need explicit protection when they configure the caller's checks. Package export and other application fields remain editable. A public suite's observed test count cannot shrink below an earlier checkpoint's count and still verify. Counts are not test identities; this is coverage preservation, not a defense against malicious code.

Snapshots currently support regular files, at most 5,000 files and 64 MB including ignored files. Symlinks/submodules and larger repositories fail explicitly. Installed dependencies count toward that limit. `.suffice-v9-checks` is reserved. General repository support beyond this bounded implementation needs a separate immutable dependency baseline and larger snapshot design.

## Evidence and limits

`result.json` records stages, tokens, cost, checks, arbitration, the selected checkpoint and a source hash. `final-source/` is the actual selected artifact. The last model message can describe a discarded candidate; use the source and check receipts as authoritative. Exit status distinguishes completed, verification failure, unverified, operational failure, budget stop and unknown cost. Zero tests, unavailable runners and missing test summaries do not establish a passing test suite.

All paid stages share a deadline and API-equivalent token allowance. Costs use pinned standard text-token prices, including cached input exactly once. They are estimates, not subscription charges or invoices. Unknown/missing usage stops additional calls and stays unknown; known spend is retained as a lower bound. Native Codex exposes no verified hard dollar ceiling here: allowance is checked between calls, so one response can overshoot. Such attempts remain in the report and are ineligible for policy-valid success.

Reviewers use a fresh empty read-only working directory, disabled optional integrations/shell and a zero-tool event audit. Native Codex does not expose a verified switch removing every tool schema. A review that emits any tool activity is rejected, but activity can occur before that audit. This is not hard tool-free enforcement. Workspace-write and local file separation are also not a proven secrecy boundary on this host.

The independent writer and arbiter can still share model blind spots. Exact quotes and bounded edits improve accountability; they do not prove assertions correct. Real quality must be measured by independent grading after actors have stopped.
