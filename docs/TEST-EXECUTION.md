# Intelligent test execution: frozen protocol v1

Model: subscription OpenAI GPT-6.1 Sol, low effort, native codemode, existing AST navigation. Source snapshot 37fb5e2 plus isolated experiment implementation. No auxiliary inference. All three arms share prompts, tool schemas, tasks, 24 model turns / 100 top-level tool calls / six-minute agent budget. Their tool-result test scheduling differs:

- unrestricted executes every requested public test.
- fixed permits the initial requested test, then tests only after at least two meaningful production edits since the last executed test of any type.
- selective executes a requested test when its kind, complete production-source digest, and test-source digest were not already executed during this attempt. It does not select individual upstream cases; it selects executions by revision freshness.

A meaningful edit changes production bytes. No-op writes do not increment checkpoint count. New custom checks invalidate selective freshness. Failures are retained; suppressed duplicates report deferred, executed:false, and never return a cached pass. Infrastructure exceptions are not recorded as completed test observations. Fixed checkpoints deliberately defer novel generated assertions until another checkpoint and may miss useful feedback; independent acceptance detects resulting errors.

All test requests including generated public checks and original upstream suites are gated. After the model session closes, the evaluator ALWAYS executes identical hidden acceptance, visible regression, and frozen upstream core regression. It verifies expected counts, no skips, model IDs, source-only edit scope and all immutable bytes. These final checks are never provided during repair. Success requires completed execution and independent acceptance/regression; partial patches are reported separately. Final test compute is counted separately and equally required. Wall time measures subprocess wall time, not CPU cycles.

Difficulty screen: a fresh historical alias-merge fix, three arms (3 attempts). Heldout: fresh merge-sentinel values, flow alias/property-only keys, whitespace-only scalar dedent; three arms, two repetitions, rotated order (18 attempts). Screening does not establish general difficulty; report baseline success/failure and policy activation before scored work. Historical revisions/reference patches are public and could be training-known. Hidden tests are independently authored API checks plus original upstream regression; reference fixes are validated before freezing. Source-only fixtures exclude docs/distribution, dependency-heavy fuzzing and pathological performance stress; exclusions disclosed in receipts.

Caps across smoke/screen/scored/retry inference: $3 known API-equivalent usage, 4 screening, 18 scored. Stop before another attempt once known spend reaches cap; a single attempt can overshoot and unknown provider charges remain unknown. No claim of exact billing. At most 100 MiB new artifacts, at least 1 GiB free C:. Concurrent root/provider campaigns can affect cache and latency. Every attempt retained. No stock Codex/Pi comparison, statistical significance or capability superiority assumed.

Efficiency view: independently accepted tasks, total cost including failures, complete-pair costs, requested/executed/deferred public tests, and public/final test wall time. Capability view: accepted solves within equal $0.75 per-arm known model-cost budgets, using identical scheduled tasks and retaining failures; report remaining budget and unknown usage. Do not infer saved model tokens from deferred local tests; no counterfactual CPU saving is established without replay. A bounded deterministic policy trace test verifies actual suppression/freshness, separately from live results.
