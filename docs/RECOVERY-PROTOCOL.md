# Failure recovery bounded protocol v1

Frozen before pilot: GPT-6.1 Sol subscription, Pi 1.2.0, low effort, same tools/navigation and 16-generation/80-tool/300-second/$0.20 observed-cost ceiling in each arm. A single provider generation can overshoot the observed-cost ceiling; all costs remain charged. Maximum $3 known inference across four screening plus at most eighteen scored attempts. Stop before further inference at the cap. Unknown usage is retained and does not count as zero. No auxiliary inference. Engineering agent work is outside benchmark inference accounting.

Normal repair continues from failed source. Treatment snapshots only the owned production allowlist after a passing full visible regression run, starting from validated baseline. Generated passing cases cannot certify checkpoints. Two distinct source digests with failed executable visible validations after edits trigger restoration of the last checkpoint. An unchanged failing test, infrastructure failure, or baseline failure cannot trigger restoration. All failed source states, diagnostic excerpts, source hashes, transcripts and costs remain retained; restoration increments the source epoch and makes tests stale. Restoration returns an explicit different-approach instruction and failure ledger. No hidden evaluation enters the loop. All source/test/tool policy bytes and baselines are hash-frozen, including Windows bytes.

Tasks are fresh historical js-yaml issues distinct from the main three-task campaign: per-document BOM handling, aliased merge source tag provenance, and empty block scalar outdent. Pinned base/fix SHAs and exact prompts live in benchmarks/recovery/tasks.mjs. All baselines fail independent behavioral acceptance while upstream reference repairs pass acceptance, seven visible regressions, and original upstream core tests. Parser exceptions are legitimate observed baseline behavioral failures; test startup/import errors are not. Source-only fixtures include production, original core tests/fixtures, package metadata, README and license; bulky docs, dist, fuzzing and stress tests excluded. No installs or builds. Historical tasks may be represented in training.

Pilot order: BOM normal then rollback; merge rollback then normal. Four screening attempts total. Difficulty criterion: at least one normal operational/acceptance failure; activation criterion: at least one actual treatment restoration. If either criterion is absent, report the pilot as inconclusive and do not claim a capability gain. A full 18-attempt score run, if justified by pilot, rotates arms across three tasks and three repetitions. Screened tasks remain marked screening-exposed; the third task is fresh after screening. Definitive evaluation requires a larger untouched hard corpus beyond this bounded experiment.

Final independent hidden acceptance, visible regression, original upstream checks and immutable-file integrity are identical across arms. Success additionally requires completion and correct model identity. Track patch acceptance separately from operational completion, actual restoration count, distinct failed states, checkpoint count, test freshness, all usage/cache tokens and latency. Cost per success includes failures. Concurrent campaigns share machine/provider: latency/cache differences are descriptive and confounded. No injected wrong patches or altered prompts manufacture activation.

Commands: `node --test tests/recovery.test.mjs`; `node scripts/prepare-recovery.mjs`; `node scripts/recovery-experiment.mjs pilot`; optional justified `node scripts/recovery-experiment.mjs score`. Launch jobs hidden with durable stdout/stderr under .suffice/recovery-runs. Never overwrite a completed campaign manifest.
