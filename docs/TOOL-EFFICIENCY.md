# Sol tool-efficiency experiment

Compare four configurations with the same GPT-6.1 Sol worker and low reasoning: control, compact printed observations, AST-based navigation, and both. No extra model calls, watcher, routing or history pruning. The baseline preserves the prior core tool behavior; all four receive the same full-observation recovery tool and safe object-field projection for public API checks.

Compact formatting changes only tool results printed to the model, after JavaScript execution. Programmatic structuredContent remains identical, so code such as `(await tools.file_read(...)).text` keeps working. Matching complete observations are rendered as concise text, preserving all returned source lines, omission counts, success/error status and actionable failure diagnostics. Passed TAP logs become status/count summaries. Full originals remain in ignored observation files and are accessible through observation_read. Unknown/free-form output is preserved; this is deterministic formatting, not LLM summarization.

Navigation adds symbols, symbol_read and symbol_references, using pinned Acorn 8.19.0 and acorn-walk 8.3.5 (about 622 KB unpacked). It indexes JavaScript declarations and class methods, returns exact line ranges and file imports, and finds syntactic identifier references in production/tests. It does not claim complete semantic resolution. Reads are paginated, omitted portions are disclosed, parse failures fall back to normal tools, and edits invalidate cached indexes.

Fresh historical node-semver tasks: rejecting numeric components after wildcards; exact zero-major caret prerelease lower bounds; prerelease-to-stable diff classification; and digit-prefixed alphanumeric prerelease parsing/coercion. Each is replayed from the parent revision of its upstream fix. Sources are ~67–72 KB compressed each. Existing seven-group regression adaptation and separate expanded hidden contracts must pass with the upstream fixes and fail without them. References/hidden checks are never available to the worker.

Main schedule: four tasks, four configurations, three repetitions = 48 attempts. Rotate configurations per task/repetition and reverse order on alternating repetitions. Freeze prompts, source, package lock, task files, acceptance, budgets and schedule before running. Do not change them during the campaign. Smoke runs use the old subset task, never the new evaluation tasks. Preserve all attempts, errors and patches; never replace failed attempts.

Budget per attempt: 6 minutes, 24 generations, 100 tool events, one provider retry. Stop at $12 in known API-equivalent estimated cost, below 5 GiB free disk, on authorization/quota errors, or after two consecutive provider/harness failures. Transient 503 text mentioning subscription is classified as service availability rather than expired authorization. No API-key fallback, Jev, or OpenRouter inference.

Metrics: frozen acceptance + regressions + completion; matched total estimated cost including failed attempts; input/cached/output tokens; latency and generation count; response formatting activation and actual before/after printed character counts; navigation and recovery calls. Unknown telemetry remains unknown. Compare compact/control, navigation/control, combined/control, combined/compact and combined/navigation. A cheaper run that loses correctness is not an accuracy-preserving efficiency win. Provider caching is observed rather than controlled. Four historical tasks remain a narrow diagnostic dataset.

Preparation: `node scripts/prepare-efficiency.mjs`. Run: `node scripts/efficiency-experiment.mjs --campaign=sol-tools-v1 --repetitions=3`. Report: `node scripts/efficiency-report.mjs sol-tools-v1`. Use a fresh campaign name after changes. Raw data lives under ignored `.suffice/efficiency-runs/`.

Pre-campaign validation: 77 harness tests passed. The first old-task smoke solved the task and used navigation but formatted zero model-visible responses because Pi merges batch outputs behind numbered text markers. The formatter was fixed to recognize those markers while preserving unknown/free-form output. The second smoke passed, used three navigation calls and formatted five responses. Neither smoke contributes to main benchmark scores or model-cost comparisons.
