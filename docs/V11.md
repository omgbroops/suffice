# V11 candidate: recover verification before repairing code

V10 combined the original Pi tool stack with the newer testing controller. It did not integrate every historical strategy, and combining components did not establish an accuracy gain. Its 27-task comparison produced 17 private passes versus native Codex's 24; seven V10 attempts stopped unverified. Four of those seven passed private grading. The public-input omissions described in [the frozen report](../reports/POLY27-LOCKED.md) also limit that comparison.

V11 is a separate development candidate on `codex/suffice-v11`. V10 source, protocol and results remain unchanged. This candidate addresses verification integration; it has no measured model-accuracy improvement yet.

## What is combined

| Self-check contract / public examples | Worker runs public checks; independent writer is prompted to cover public exports and examples | Existing project tests remain visible. Prompting does not guarantee coverage. |
| BM25 localization (v5), import/reverse-dependency graph | Not integrated in this runner | Adjacent original interfaces/docs are now selected for reviewers. That is not BM25 or a resolved dependency graph. Larger-repository localization needs its own implementation and ablation. |
| Blind test writer (v6) | Enabled | Receives the public request and original source context, never the worker's implementation/history. |
| Multiple candidates and planner (v6) | Not enabled | Historical v6 lagged the simpler v5b on r27; extra stages need evidence. |
| Test-first pipeline (v7) | Not enabled | The writer runs after implementation but remains blind. No claim that this reproduces v7's full pipeline. |

| Watchers, semantic retrieval, revision records, delegation, pruning | Retained in historical experiments; not enabled here | The handoff reports no established accuracy advantage, extra cost, or lost work. Turning all of them on would not be a validated merge. |

## Recovery policy

1. Run caller checks and let Luna implement. Preserve existing tests/configuration and checkpoint source.
2. Select original public interfaces, referenced adjacent helper sources and documentation. Explicit `contextPaths` come first. Share the same original context with the independent writer and arbiters. Never infer requirements from worker changes.
3. Generate one test file with 1–4 separate exact citations to the public task or supplied original source. Invalid JSON, paths, commands or citations get one retry with the validation diagnostic. A second invalid result remains unverified.
4. Quarantine a failed, unavailable or inconclusive generated suite before arbitration. Keep its observed status, count and output in receipts. All its candidate outcomes remain unverified while disputed, including a later passing outcome.
5. An arbiter may confirm an implementation defect, propose one bounded unique test correction, or identify ambiguity with a concrete clarification question. An unresolved decision or still-failing correction gets one further verification-recovery call. It cannot silently drop the suite or request an implementation rewrite.
6. Recheck all checkpoints after a correction. A confirmed generated defect requires an executed failing test with retained test count. Missing runners, zero tests and compile-only generated failures remain conservative verification limits. Real failed caller checks retain their failure status even when compilation reduces their test count.
7. Repair confirmed failures only, then allow one expert takeover if they remain. Disputed generated diagnostics are excluded from repair/takeover targets. Recheck the same suite and restore the best candidate. Persistent ambiguity remains unverified with its clarification question.

The controller keeps cost/deadline guards at every model boundary. Unknown cost stops further calls. Counts in the final result refer to recorded model stages. Protected checks are restored even if the first model stops before checkpointing, and every restoration is surfaced as a `policyViolations` entry. `completed` means the available public checks passed; it does not mean private acceptance or full specification coverage.

Exact citations establish provenance, not logical entailment. A model can still misread a requirement, write a weak test, or suggest a weak count-preserving correction. Test counts cannot prove assertion coverage. These are explicit limitations of the candidate.

## Use

```powershell
npm run test:v11
Get-Content -Raw C:/work/request.json | node scripts/v11-run.mjs
```

The request uses [the existing fields](V9.md#run), with `strategy: "v11"`; `luna`, `sol`, and `ladder` remain comparison strategies. Models and default efforts match V10. The generic request still defaults to a $0.50 allowance and ten-minute deadline; benchmark plans must explicitly supply their authorized allowances. No new live campaign has been started by creating this candidate.

The reserved generated-test directory remains `.suffice-v10-checks` for compatibility with the existing six-language public helper. It is an internal helper namespace, not the reported runtime version. Context selection includes at most 12 complete files, 12,000 UTF-8 bytes each and 48,000 total, plus up to 100 eligible paths. Oversized/count-limited files are listed as omitted rather than truncated. Specify critical interface paths explicitly. This selection is not a security boundary.

The unchanged Pi adapter, snapshot limits and host-execution limitations in [V10](V10.md) apply. The controller has no hidden-grader input or dependency. Use external isolation for untrusted repositories.

## Validation and next benchmark

The V11 tests use newly authored **development-only** label-normalization and public-interface scenarios, deterministic model replies, and real Node test execution. They verify controller transitions and evidence boundaries; they do not measure model coding quality. Existing V9/V10 tests check that shared behavior is preserved.

Offline validation passes 35 V11 tests and 67 existing V9/V10 regression tests (102 total). No paid model calls were used for this validation.

Before a live quality comparison, freeze V11 and a fresh independently selected cohort. Publish complete public API contracts, keep existing public tests visible, and withhold only new acceptance cases. Match original source, model identities/efforts, actor isolation and time/resource allowances across V11, frozen V10 and native Codex. Run every actor before introducing private acceptance tests. Report acceptance, unverified/operational outcomes, policy restorations, total cost and latency separately. Reusing the diagnosed 27 exercises can supply development evidence, never a fresh held-out improvement claim.
