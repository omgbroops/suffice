# Pi resources in Suffice

Reuse Pi settings.json, mcp.json, skills and prompts under Suffice home. Load resources in the shared harness, retain Pi project trust and make MCP tools reachable through Codemode. Desktop settings use the existing navigation and composer-material cards. Resource discovery in settings must not execute extension code. User actions can add/edit Markdown skills/templates, edit MCP configuration, enable/disable resource paths and install/update/remove Pi packages through its SDK. Existing running agents keep their configuration until explicit reload or the next session. No background package installs or project trust bypass.

The resource settings omit a Session tools page and repeated reload notices. Modal text inputs and textareas share a single fill and outline, with a white fill in light mode. Product system instructions explicitly identify the agent and host as Suffice; Pi names remain for engine-specific features.

User messages reuse the composer's surface in light and dark mode; assistant responses remain plain. Soft horizon adds a static, resize-aware navy/amber atmospheric background without changing the selected preset or Pixel horizon default. Windows taskbar metadata uses a profile-local Suffice launcher shortcut and a multi-size ICO while keeping the existing app ID and profile.

Compaction and user stops are transcript checkpoints, drawn as centered muted labels between fading horizontal rules. Compaction updates one pending checkpoint in place; success distinguishes automatic and manual compaction. Failed or cancelled compaction never reports success. User stops preserve partial output and return a structured interrupted result. Persist only checkpoint metadata alongside the engine session; reconstruct the display from the canonical compaction-aware projection, without changing model context or rendering the private summary as prose. Older aborted assistant messages also render an interruption checkpoint. Genuine run failures remain errors.

Approval requests replace the contents of the existing composer surface rather than opening native dialogs. Show the exact requested code/command, explicit Allow/Deny actions and a bounded scroll preview. Keep pending requests per thread, preserve the draft, dismiss resolved requests, and route each answer to its original thread/request ID. Approval never follows merely from pressing Enter in the original prompt.

Approval previews use the selected code font and the shared Executed code syntax renderer. Pending approvals use the sidebar attention state instead of Working. Hover cards only show a previous error for a currently failed run. Partial tracking alone does not produce a changes badge; nonzero recorded edits still show their counts and partial marker. Premature stream errors are displayed with the selected service name while preserving the engine error in its session log.

A renderer refresh reconnects to a live snapshot rather than an empty transcript. It restores pending approvals and handles explicit run completion even after the original IPC caller disappears. Counts in hover cards share sidebar addition/deletion colors. OAuth callback branding uses the saved interface font and Suffice mark, with an Inter fallback and no account data passed to the browser page. Windows development launches use an independently branded executable copy while preserving Electron's shared original.
