Public behavioral reproduction: i01

Expected behavior: With default redirect behavior, awaiting fetch inside try/catch rejects with a catchable error for the invalid Location. The public issue does not require a specific error class or message.

Source references:
- https://github.com/node-fetch/node-fetch/issues/1386 — Original reproduction uses //super:invalid:url%/ and expects an invalid URL to be caught and an appropriate error returned.
- https://github.com/node-fetch/node-fetch/blob/a6663eb141a5b2a1c37aafeeb9480bfdc9de815a/src/index.js#L123-L145 — Pre-fix public redirect response handling.

Executable code (`node reproduce.mjs`, complete clean source copies beside it):
```js
import http from 'node:http';
import {once} from 'node:events';
import fetch from './source/src/index.js';
const invalidLocation = '//super:invalid:url%/';
const server = http.createServer((request, response) => {
  response.writeHead(302, {Location: invalidLocation});
  response.end();
});
server.listen(0, '127.0.0.1');
await once(server, 'listening');
console.log('requesting local redirect; awaiting fetch inside try/catch');
try {
  await fetch(`http://127.0.0.1:${server.address().port}/`);
  console.log('UNEXPECTED: fetch resolved');
  process.exitCode = 1;
} catch (error) {
  console.log('CAUGHT: fetch rejected with an error');
  console.log(JSON.stringify({name: error.name, message: error.message}));
} finally {
  server.close();
}
```
